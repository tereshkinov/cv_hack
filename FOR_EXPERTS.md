# CV Office — запуск и настройка для экспертов

Проект обрабатывает записи с нескольких камер и показывает в браузере сквозные ID, счётчики и траектории на плане. В репозитории есть готовый пример на пяти камерах. Для просмотра достаточно запустить сервер.

## 1. Откройте готовое демо

Понадобятся Git, Python и браузер. Для macOS используйте Python 3.13. На Windows выполните команды в Ubuntu через WSL 2. Просмотр проверен в Ubuntu 24.04 с Python 3.12. Интернет нужен для клонирования и установки пакетов.

```sh
git clone --branch main https://github.com/tereshkinov/cv_hack.git
cd cv_hack
git checkout --detach 31f60931702b52ac2132958cdd4392f019b6b7e8
python3 -m venv .venv-demo
.venv-demo/bin/python -m pip install numpy==2.5.4 opencv-python-headless==5.0.0.93
.venv-demo/bin/python -m src.app --port 8765
```

На первом запуске дождитесь сообщения `Office editor:` в терминале. Сервер автоматически распакует план, видео и готовый результат из `demo/`. Откройте [демо на пяти камерах](http://127.0.0.1:8765/review?run=20261107-205603-b5eb494b) или [редактор проекта](http://127.0.0.1:8765/). Если порт занят, поменяйте значение `--port` и номер в адресе браузера. Для остановки сервера нажмите **Ctrl+C**.

Нажмите **«Смотреть»**. Общая шкала управляет всеми ракурсами. Около **84–86 с** трек `g8` переходит с камеры 4 на камеру 5 и сохраняет ID. Выберите `g8` в таблице, чтобы увидеть его путь на плане. Для демонстрации взяли первые три минуты записи с каждой из пяти камер, чтобы сократить время обработки.

## 2. Установите зависимости для новой обработки

Остановите сервер демо, если хотите использовать тот же порт. На macOS с Python 3.13 из корня проекта выполните `./setup.command`. Скрипт установит зависимости в `.venv`, подготовит модели и запустит приложение. На Ubuntu или WSL выполните команды ниже. Если Ubuntu сообщает об отсутствии `ensurepip`, установите системный пакет `python3-venv` и повторите создание окружения.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r src/vision/requirements.txt
.venv/bin/python -m src.demo_bundle
.venv/bin/python -m src.vision prepare
.venv/bin/python -m src.app --port 8765
```

Для запуска с полным набором зависимостей используется отдельное окружение `.venv`. Детектор YOLO11n и ByteTrack поставляются через Ultralytics. OSNet извлекает признаки внешности. PyTorch запускает модели, OpenCV читает видео, NumPy используется для расчётов. Веса уже входят в демокомплект. [Зависимости для Linux](src/vision/requirements.txt) · [Версии для macOS](src/vision/requirements-lock.txt) · [Модели и лицензии](src/vision/THIRD_PARTY.md)

## 3. Настройте свои камеры и видео

Готовый проект уже настроен для записей из комплекта. Чтобы создать отдельную конфигурацию для своих видео, остановите сервер и запустите его из корня проекта с другим файлом настроек. При первом запуске с таким путём редактор откроет пустой проект.

```sh
.venv/bin/python -m src.app --port 8765 --project configs/expert.local.json
```

1. В разделе **«Настройка»** нажмите **«Загрузить план PNG / JPEG»**. Если известны размеры помещения, выберите метры и нажмите **«Применить размеры»**. Без масштаба используйте условные единицы.
2. Нажмите **«Добавить камеру»** и укажите её положение на плане. В карточке камеры нажмите **«Загрузить видео»** или выберите запись в поле **«Источник кадра»**, если она уже находится в `data/raw/`. Повторите для каждой камеры.
3. У синхронизированных файлов оставьте **«Начало видео, с»** равным нулю. Если записи начинаются в разное время, задайте смещения так, чтобы одно и то же событие на разных камерах совпало на общей шкале. В **«Общей зоне обзора»** отметьте камеры, которые видят один участок. В **«Можно перейти к»** отметьте допустимые переходы из выбранной камеры. Обратное направление задаётся отдельно.
4. Нажмите **«Показать кадр»** и выберите **«Разметить точки»**. Укажите одну и ту же физическую точку пола сначала на кадре, затем на плане справа. Добавьте минимум четыре пары, распределённые по видимой области пола, и нажмите **«Рассчитать привязку»**. Проверьте её через **«Проверить кликом»** на точке, которую не использовали при разметке.
5. Если детектор реагирует на отражения или экраны, задайте полигоны в блоке **«Разрешённый пол и исключения»**. Дождитесь статуса **«Сохранено на компьютере»**. Кнопка **«Скачать проект»** выгружает конфигурацию в JSON, а **«Открыть JSON»** загружает её обратно. Видео и план хранятся отдельно.

## 4. Обработайте видео и проверьте результат

1. Откройте **«Просмотр и запуск»** → **«Параметры обработки»**. Выберите **CPU**. Установите **«Лимит видео, с»** в `0` для обработки полных файлов или задайте короткий лимит для первой проверки. Значение `1` в поле **«Каждый N-й кадр»** включает обработку каждого кадра.
2. Нажмите **«Обработать видео»**. После статуса **«Готово»** выберите этот запуск, профиль **«Переходы по траекториям + зоны пола»** и нажмите **«Проверить фрагменты»**. Профиль применяет настроенные зоны пола и исключения, например для зеркал и экранов, и автоматически пересчитывает межкамерные ID по сохранённым детекциям. Ход задачи и ошибки видны в журнале обработки.
3. Проверьте сохранение ID при переходе между камерами и раздельные ID у людей, которые видны одновременно. Чтобы разобрать спорные рамки, включите **«Показать кандидатов»** или **«Показать отфильтрованные»**. Каждый запуск хранится отдельно в `runs/product/<ID запуска>/`.

Межкамерное сопоставление и правила завершения треков реализованы в проекте. Алгоритм использует геометрию, движение и при неоднозначности признаки внешности. В готовом демо окно ожидания составляет 60 секунд, поэтому быстрый возврат после выхода из всех зон обзора может сохранить прежний ID.
