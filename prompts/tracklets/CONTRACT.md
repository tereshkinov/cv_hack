# Общая интеграция: фрагменты и свидетельства

Это предложенный интерфейс реализации второго этапа, не изменение ТЗ организаторов. Агент 1 поддерживает его совместимость; агенты 2/3 реализуют поставщиков. Уточнения интерфейса фиксируются здесь до интеграции. Не меняйте старые Observation/Camera/GlobalTrack молча.

## Общая база и разделение

Код: origin/tuning/scoring, снимок 4c6d61acd38ed6fb24deca1b04e4e3084bbc1001. Промпты: актуальный main. После получения кода прочитайте актуальные prompts/tracklets/*.md из main: их ещё нет в исходном снимке. Не переносите вместе с промптами старые версии модулей из main поверх экспериментальной базы.

- Агент 1: tuning/scoring; lifecycle кандидатов, выделение/разделение фрагментов, engine/reconcile, итоговые веса, назначение и пересмотр ID, экспорт, UI, интеграция.
- Агент 2: tuning/tracklet-geolocation; geolocation.py/boundary_geometry.py, пространственные признаки и их проверки.
- Агент 3: tuning/tracklet-appearance; vision и boundary_appearance.py, визуальные признаки и их проверки.

Агенты 2/3 не импортируют новые реализации друг друга. Входом служит список существующих Observation; служебные структуры могут быть отдельными dataclass либо документированными dict, не обязаны становиться JSON основного контракта.

## FragmentWindow

Минимальные поля: fragment_id, camera_id, исходные references `(camera_id, frame_index, local_track_id)`, start_s, end_s, упорядоченные observations. Все времена уже в общей шкале. head/tail выбираются по времени видео, не числу кадров: исходный ориентир окно 1–2 с с возможностью расширения для редких признаков. Точный параметр фиксировать в эксперименте, не считать новым требованием владельца.

Если агент 1 виртуально разрезал локальный трек, исходные references остаются прежними; новые fragment_id не подменяют local_track_id в исходнике. Произвольный набор одного gid до пересборки не считается гарантированно чистым фрагментом. Число независимых временных наблюдений отличается от числа камерных рамок.

## BoundaryEvidence

Поставщик принимает конец A, начало B и режим (`same_camera_recovery`, `simultaneous_overlap`, `sequential_transition`). Минимальный результат:

- available и reason;
- value либо None с явно описанной шкалой (cosine/мягкая поправка/нормированное расхождение);
- reliability с описанием составляющих и уже применённых весов;
- support_count — независимые подтверждения, не просто число дублирующих кадров;
- детали: времена, диапазоны/разброс, пригодные части тела либо ожидаемая область и coordinate_units.

Отсутствие данных не равно отрицательному свидетельству. Нельзя смешивать шкалы или применять confidence/reliability повторно. Агент 1 переводит результаты поставщиков в общую оценку; поставщики ID не назначают. Сохранить legacy-интерфейсы и отдельные переключатели, чтобы сравнение с предыдущей версией оставалось возможным.

## Актуальное окно сохранения ID

По уточнению владельца от 7 ноября: допустима пропажа до 60 секунд включительно. Более длинный пропуск начинает новый эпизод. Это возможность восстановления по свидетельствам, а не автоматическое объединение похожих людей. Явный выход и надёжные пространственные противоречия имеют приоритет. Экстраполяция движения ограничена коротким горизонтом 4 секунды.

## Кандидаты и итоговый учёт

Стартовый эксперимент нового трека: 3 независимых момента наблюдения за 0.4–1.0 с; агент 1 должен точно определить параметры окна. Это предложение команды, не правило организаторов. Проверка восстановления существующего эпизода выполняется до отбрасывания короткого нового фрагмента. Кандидаты/отказы сохраняются с причиной, их можно показать в диагностике. Подтверждение возвращает начало к первому наблюдению. Новая схема экспорта должна явно различать подтверждённые и неподтверждённые результаты и сохранять соответствие всем исходным наблюдениям; интерфейс читает старые запуски как раньше.

Нельзя склеивать одновременно видимых независимых людей одной камеры, обходить закрытие эпизода или доказывать истинность связей их малым количеством. Одновременные ракурсы одного человека в общих зонах допустимы. На уровне объединённой группы проверяются все ограничения, включая транзитивные конфликты.

## Проверка и передача

Сравнение: прежний raw; только подтверждение кандидатов; только оконное восстановление; только пересборка; итоговое сочетание. Сохранять одинаковые детекции/интервал и фиксировать изменённые компоненты. Отдельно учитывать ложные склейки, разрывы, потерянные реальные короткие появления, краткие срабатывания без подтверждения, качество переходов и время. Число однокамерных треков — диагностическая статистика, не целевая функция.

В отчёте указать, есть ли независимые точки пола и человеческая разметка ID. Без них не обещать точность. При отсутствии реальных файлов допустимы явно синтетические сценарии и запуск для интегратора. Передавать отдельный коммит своей ветки; слияние в main — после одобрения владельца.
