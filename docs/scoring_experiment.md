# Агент 1: эксперимент балансировки свидетельств

Ветка `tuning/scoring`, исходный тег `baseline-floor-v1`. Бейзлайн по умолчанию сохранён; новый режим включается отдельно. Модули FloorMatcher и признаков внешности не менялись. Глобальные пороги внешности не снижались.

## Решение

После существующих ограничений графа/времени/локальных интервалов оценивается отклонение сходства внешности от порога. Его вес зависит от confidence, размера и обрезки bbox, а также confidence галереи. Это доступные суррогаты качества: освещение, размытие и перекрытие напрямую ещё не измеряются. Геометрия использует существующий знаковый бонус FloorMatcher. Дополнительный адаптер снижает его вес при отсутствующих проекциях, экстраполяции за границы опорных точек и короткой истории. Границы опорных точек проверяются по прямоугольнику, не по точному выпуклому четырёхугольнику. Ошибка на опорных точках не используется как доказательство точности всей сцены.

Итоговая оценка: `T + (appearance-T)*(0.5+0.5*appearance_quality) + topology*(1-0.5*geometry_quality) + geometry*geometry_quality*k`, где k=1.5 для поддержки и 1 для штрафа. Отсутствующая геометрия нейтральна. Внешность ниже 0.45 не компенсируется геометрией. Геометрическое противоречие ниже −0.10 при доверии не менее 0.6 отклоняет связь даже при похожей одежде. Эти коэффициенты — проверяемые эвристики, а не вероятности или обученная калибровка.

Онлайн-проверка неоднозначности видит конкурентов до 0.12 ниже порога, но назначаются только кандидаты выше порога. При неоднозначности создаётся предварительный отдельный трек, который может объединить существующее офлайн-уточнение. Новый алгоритм не исправляет ошибки внутри непрерывного локального ID.

Связь без достаточного запаса не обновляет онлайн-галерею до сильного подтверждения либо трёх подтверждений за минимум 0.4 секунды. Проверки выполняются относительно старой галереи. Это защищает от немедленного самоподтверждения, но не отменяет ошибочное назначение ID; офлайн-галерея по-прежнему использует наблюдения предварительных групп и тоже может ошибаться.

## Запуск

В просмотре завершённого результата нажать «Тест балансировки ID». Он создаёт отдельный запуск из готовых наблюдений/признаков/JPEG без чтения видео и инференса. Обычные кнопки сохраняют прежний алгоритм.

CLI ассоциации: к прежним аргументам добавить `--decision-mode balanced`; по умолчанию `baseline`. Для геометрии передать `--project configs/office.local.json`.

В эксперименте экспортируется `decisions.jsonl`: отдельные компоненты оценок и причины для онлайн/офлайн-кандидатов. `accepted` означает прохождение порога поддержки, а не окончательную связь. `selected_online` показывает выбор первого прохода до офлайн-переименования. Фактические окончательные ID находятся в assignments.jsonl. Изменение галереи отмечается в назначениях, количество заблокированных обновлений — в reconciliation.json.

## Контрольное сравнение

Одинаковые наблюдения, признаки внешности, проект, манифест камер и пороги; первые 180 секунд каждой камеры, 2272 наблюдения. Текущий граф содержит добавленное владельцем перекрытие cam03 ↔ cam04.

- Бейзлайн: `20261107-092940-57630200`, 55 треков, полный пересчёт 6.29 с.
- Эксперимент: `20261107-092949-4fbc00ec`, 60 треков, полный пересчёт 5.77 с.
- 84 обновления онлайн-галереи отложены.
- 10 пар локальных эпизодов с разными решениями и промежутком не более 15 с подготовлены к ручной проверке.
- Различия отношений между парами наблюдений: 5231 разделена, 1560 объединена. Это изменения разбиения, НЕ FP/FN.

Прирост точности не установлен. Больше ID может означать и устранение ложных склеек, и лишние разрывы. Тот же материал использован для разработки, независимая проверка ещё не проводилась. Бейзлайн не заменён.

Команда сравнения:

```sh
.venv/bin/python scripts/compare_scoring.py --baseline runs/product/20261107-092940-57630200 --experiment runs/product/20261107-092949-4fbc00ec --output runs/scoring-validation/comparison
```

Скрипт требует одинаковые входные наблюдения, проект, камеры и настройки. Выдаёт comparison.json и review_cases.csv с пустыми полями human_same_person/comment; ручные ответы не используются для назначения ID.

Проверка синтаксиса браузерного скрипта и ruff прошли.
