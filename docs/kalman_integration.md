# Интеграция актуального main и Kalman в сеточный прототип

Основа прототипа b472b6c, main d160d38. Ветка tuning/kalman-motion (338283f) уже включена в main через c898628; её второй раз не применяли. Общие kalman_motion.py, geometry_policy.py и изменения BoundaryGeometryMatcher взяты из main. Сеточная калибровка и контрольные точки сохранены.

## Что объединено

1. Прогноз положения/скорости Калмана: история до 1.6 с, минимум три независимых момента на интервале 0.4 с; разрыв более 0.8 с сбрасывает старую историю. Прогноз ограничен 4 с; неопределённость растёт со временем и ошибкой синхронизации.
2. Скорость у выхода поступает в модель движения по графу офиса, в том числе при relative-плане с meters_per_unit. При остановке или слабой/устаревшей оценке используется популяционный профиль, а не выдуманная точная скорость.
3. Настроенный маршрут при переходе между камерами проверяется до прямолинейного прогноза через стены. Геометрия пола и маршрут не суммируются повторно.
4. Одновременные позиции сравниваются общим FloorMatcher с учётом sync_uncertainty_s. Удалена отдельная более узкая оценка радиуса в прототипе. Когда оценка пола слаба, доступное более надёжное движение рамки той же камеры не теряется.
5. Общая нормализация геометрического score из main. Низкая надёжность явного маршрута уменьшает уверенность, но не означает автоматическое требование внешности при единственном пространственном кандидате. Возможность находиться где угодно после длинной пропажи сама по себе не доказывает ID: для blind_gap_reachable сохранена осторожная проверка внешности.
6. Перенесена защита от транзитивной склейки одновременно видимых фрагментов без прямой пространственной поддержки. Надёжные физические противоречия запрещают объединение.
7. В интерфейсе доступны выбор «Калман / прежний прогноз», собственный режим неоднозначностей и два режима из main. Cached-пересчёт использует выбранные параметры. Ожидание 60 с и трёхминутный лимит сохранены.

## Имена режимов

В main имя geometry означает строго геометрический режим. Прежний прототип с таким именем переименован в geometry_ambiguity; активный локальный проект перенесён на это имя. geometry_visual — режим main с ограниченным визуальным подтверждением. CLI для geometry/geometry_visual требует --fragment-mode rebuild. Прототип geometry_ambiguity сам начинает с локальных фрагментов и не использует предварительную визуальную склейку.

Старый UI-профиль `geometry` оставлен совместимым: он выбирает geometry_ambiguity. Новые профили `geometry-only` и `geometry-visual` выбирают режимы main. Поэтому старые команды CLI с --decision-mode geometry следует проверить: теперь это значение имеет смысл из main.

В geometry_ambiguity внешность применяется при конкурирующих пространственных гипотезах либо при широкой неопределённости минутного пропуска. geometry_visual использует отдельную ограниченную поправку из main; это другой экспериментальный режим.
