# Решения и открытые вопросы
- Источники: фото слайдов 2-9 от 06.11.2026 (слайд 6 снят дважды); уточнения владельца в чате. Предварительный PDF не заменяет фактическое ТЗ.
- Команда: рамки допустимы; офлайн; собственные тестовые видео; оборудование не ограничено.
- Выбрано для прототипа: timeout 10 с вместо ранее обсуждавшихся минут; конец трека по последнему наблюдению.
- Технические предложения: формат JSON/JSONL и структура каталогов. Стек и модели ещё не выбраны.
- Открыто: вид графической траектории; надёжное событие выхода; граница готового межкамерного решения.
- Не подтверждены организаторами: слабое оборудование, серверная обработка, городская карта, целевые FPS и численная точность.
- Общий timeout может сохранить ID при быстром выходе и возвращении: известное отклонение от строгого правила выхода.

- После первого прогона на данных организаторов: профиль приложения обновлён до 15 с ожидания общего ID, 5 с локального буфера, лимит отладки 180 с на камеру (0 — полный ролик). Пороги 0.72/0.62, ambiguity margin 0.03; бонус перекрытия 0.04, направленного перехода 0.02. Новый локальный ID на той же камере разрешено восстановить по внешности и положению, при отсутствии пересечения интервалов. Раннее решение о 10 с заменено этим профилем; автономный CLI ассоциации оставлен совместимым со старыми примерами.

- Бейзлайн геолокации: ручная четырёхточечная привязка пола участвует в сопоставлении ID мягким бонусом/штрафом и прогнозом короткого движения. Отдельный пересчёт ID использует сохранённые признаки без повторного запуска моделей. На текущем локальном примере 64 → 57 треков; точность без ручного эталона не измерена.

- Последнее уточнение владельца: человек может отсутствовать до одной минуты без обязательной смены ID. Текущий timeout приложения и CLI — 60 с включительно; после более длинного отсутствия новый эпизод. Это окно поиска совпадения, не автоматическое объединение. Прогноз движения остаётся коротким, явный выход закрывает эпизод. Старые эксперименты с 15 с сохраняются для сравнения.
