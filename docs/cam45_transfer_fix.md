# Переход cam04 ↔ cam05

## Причина
В прогоне 20261107-163635-4b8582af калибровки пола расходятся около перехода. Фрагменты f21 → f46 (25.5 → 26.4 с) дают около 11.33 м за 0.9 с; f30 → f34 (84.0 → 85.8 с) — около 11.4 м за 1.8 с. Проверка скорости отвергала визуально подтвержденные соответствия.

## Изменение
Добавлены конфигурируемые handoff_portals: пары нормированных полигонов выхода/входа, направления движения и временное окно. Для решения нужны оба полигона, устойчивое движение в ожидаемую сторону и допустимое время. Одна точка, неподвижный объект, обратное направление или большой разрыв не подходят. Конкуренция кандидатов и ограничения графа сохраняются. При отсутствии портала применяется прежняя геометрия.

Для cam04 → cam05 используется выход слева и вход в дальней части коридора, окно до 5 с, ожидаемый разрыв 1.4 с. Обратный портал настроен симметрично и пока требует ручной проверки. Порог и надежность являются предварительными настройками, а не измеренной вероятностью. Алгоритм не содержит специальных ID или времен конкретных людей.

Конфигурация сохранена в configs/office.local.json и локальном пресете configs/presets/office-cam45-transfers-20261107.local.json. В редакторе порталы показаны оранжевым, для каждого есть переключатель. Изменять полигоны порталов пока нужно в JSON. Узкий API POST /api/handoff-portals принимает объект {"portals": [...]} и сохраняет остальные поля проекта. Старое автосохранение редактора также сохраняет порталы.

53 ручные пары привязки, маски пола, масштаб, смещения времени и параметры обработки не изменены. Портал дает свидетельство связи треков; он не исправляет координатный скачок на схеме и не подменяет калибровку пола.
