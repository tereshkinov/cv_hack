# Сеточная калибровка и геометрическое сопоставление

Ветка tuning/mesh-geometry, контрольная сборка main сохранена. Активный проект и прежние пресеты продолжают хранить пользовательскую четырёхточечную привязку. Дополнительные измеренные соответствия не выдумывались. Резервная копия: outputs/office-before-mesh-20261107-163557.json. Проверено равенство cameras (включая video_points, plan_points, calibration), walls и room до и после реализации. В обработке выбрана geometry, сохранены лимит 180 секунд и ожидание ID 60 секунд включительно.

## Как настроить сетку

1. Откройте http://127.0.0.1:8765/ и выберите камеру.
2. В «Метод привязки» выберите «Локальная сетка: 4–128 точек». Исходные пары сохранятся.
3. Нажмите «+ Добавить пару». Отметьте точку пола в видео, затем то же реальное место на плане. Добавляйте точки по границам и внутри рабочей области, особенно у поворотов и там, где искажение заметно. Не выбирайте столы/стены вместо пола.
4. Сетка пересчитывается автоматически после завершения пары, также есть кнопка расчёта. На обеих поверхностях видны соответствующие треугольники. Перепутанные пары, складывание и перекрытие треугольников отклоняются.
5. «Проверить кликом»: нажмите независимую точку на кадре, затем её реальное положение на плане. Ошибка сохранится отдельно от опорных точек. Контрольные точки не участвуют в построении сетки; ошибки пересчитываются по текущей версии привязки.
6. Весь проект сохраняется автоматически, экспортируется JSON и поддерживается существующими пресетами. Вернуться к четырёхточечной модели можно при четырёх парах; дополнительные пары автоматически не удаляются.
7. В просмотре выберите готовый запуск, профиль «Геометрия + внешность при неопределённости», нажмите «Проверить фрагменты». Это использует готовые детекции и эмбеддинги. Для полного прохода выберите «Сопоставление ID → Геометрия» в параметрах обработки.

При четырёх точках сетка имеет только два треугольника и не получает новой информации о дисторсии. Для перспективной камеры четырёхточечная гомография может быть точнее такой грубой кусочной модели. Смысл нового режима — в дополнительных реально измеренных парах. Криволинейное искажение приближается локальными треугольниками; гладкая модель линзы не калибруется автоматически.

## Что реализовано

- Общий модуль src/floor_mesh.py: Delaunay-триангуляция плана (OpenCV, без новых зависимостей), локальное аффинное отображение, прямое/обратное преобразование, проверка ориентированности и глобального перекрытия треугольников.
- Старая гомография поддерживается. Импортированные матрицы/треугольники пересчитываются по опорным точкам. Поддержаны до 128 опорных пар и 64 независимых контрольных точек камеры.
- Геометрический режим начинает с локальных треков силуэтов, минуя предварительную склейку по внешности. Оценка объединения использует синхронные позиции, короткий прогноз движения по полу, движение рамки внутри камеры и граф маршрутов. Сохраняются общие ограничения назначения и поиск нескольких гипотез существующего fragment solver (beam 24, без гарантии глобального оптимума).
- Внешность не используется при однозначной надёжной геометрии. При близких конкурирующих пространственных гипотезах или низкой надёжности геометрии применяется OSNet. Если данных недостаточно, связь откладывается. Надёжное геометрическое противоречие не отменяется похожей одеждой.
- После долгой пропажи проверяется достижимость, без экстраполяции скорости на минуту. Достижимость сама по себе не доказывает ID: для слабой геометрии требуется сильное визуальное свидетельство. Явный выход и пропуск более 60 секунд закрывают эпизод.
- Неполная видимость: при обрезанных ногах или сильном изменении высоты силуэта допускается краткая поддержка по горизонтальному движению рамки той же камеры (до 1.5 с), с пониженной надёжностью. Координаты невидимых ног не выдумываются и не рисуются. Без достаточной информации новая связь может остаться неразрешённой.
- Внутри сетки используется интерполяция. Для сопоставления допустима только малая экстраполяция (барицентрический выход не более 0.1 и расстояние до оболочки не более 2.5% её диагонали), надёжность 0.25. На траектории такая экстраполяция не отображается. За большей границей сетки точка неизвестна.
- Общие зоны выводятся из пересечений размеченных областей пола и добавляют возможность сопоставления камер в геометрическом режиме. Они видны в редакторе. Это гипотеза по размеченным видимым площадкам: выпуклая оболочка не описывает внутренние непросматриваемые отверстия/окклюзии стенами. При необходимости их следует покрывать отдельными действительно видимыми областями в следующем расширении.
- Оценки и причины сохраняются в fragment_graph.json, контрольные ошибки — в reconciliation.json. Все исходные наблюдения сохраняются. Неизвестная геометрия не превращается в отрицательное свидетельство и не допускает произвольную склейку только по фото без пространственного основания.

## Проверка

170 тестов: `.venv/bin/python -m pytest src -q`. Проверены нелинейная сетка, независимое промежуточное положение, обратное отображение, некорректные пары, области вне сетки, импорт, сохранение, автоматическая общая зона, уникальная позиция без эмбеддингов, противоречие при одинаковой одежде, два близких человека с разной внешностью, неразрешённость без внешности, обрезанные ноги, геометрический скачок локального ID, явный выход и граница 59.999/60/60.001 с. Проверен cached job геометрического режима без декодирования видео и без нейросетевого прохода. Ruff, JS node --check и git diff --check пройдены.

Редактор проверен в браузере на отдельной копии проекта (порт 8767): переключение на сетку, сохранение существующих четырёх пар и добавление пустой пятой строки. Рабочая пользовательская калибровка при этой проверке не менялась.
