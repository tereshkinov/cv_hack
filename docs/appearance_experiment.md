# Агент 3. Осветление и признаки внешности

Исходная версия — `baseline-floor-v1` (`f01cec7`). Изменения относятся к модулю vision и экспериментальному запуску. Основной режим остаётся `off`. Эксперимент не меняет веса, детекции, локальные ID, геометрию и правила глобальной ассоциации. Для включения из интерфейса агенту 1 нужно передать параметры в `src.vision.pipeline.Options`.

## Что изменилось

- `src/vision/appearance_preprocess.py` поднимает яркость тёмных кропов перед OSNet. Гамма применяется через LUT к каналу Y в YCrCb. Решение зависит от центральной части кропа. Кропы с медианой Y от заданного порога, с 75-м перцентилем Y ≤ 12 или с 95-м перцентилем Y ≥ 240 остаются исходными. Стартовые настройки — гамма 0.8 и порог 80 из 255. Это параметры эксперимента, их нужно проверить на записях команды.
- В `src/vision/embeddings.py` и `pipeline.py` обработка выполняется после отбора кропов. Формат Observation v1 сохранён. Для политики гаммы используется отдельный `embedding_model_id` с параметрами. Оригинал и гамма имеют по 512 L2-нормализованных компонент. Экспериментальный `combined` имеет 1024 компоненты и отдельный ID. Косинусное сходство таких векторов равно среднему сходств `raw ↔ raw` и `gamma ↔ gamma`. Этот режим использует два прохода OSNet.
- `src/vision/clothing_color.py` сохраняет гистограммы Lab по компонентам a,b для центральных верхней и нижней зон. Ненадёжные пиксели исключаются по яркости и перекрытию соседними рамками. Сравниваются только зоны, доступные с обеих сторон. Форма рамки служит приближением для зон одежды. Гистограммы из исходных кропов сохраняются отдельно для оценки и не влияют на ID.
- `src/vision/appearance_experiment.py` пересчитывает признаки по исходным кадрам и зафиксированным рамкам. Новые JSONL сохраняют строки, порядок, времена и ключи исходного экспорта. Для каждого сравнения используется один режим по всем камерам. Операция «Пересчитать ID по привязке пола» в продукте читает прежние признаки. Для получения новых признаков нужен отдельный запуск.

## Запуск на материалах команды

Из корня репозитория, с установленным окружением проекта и проверенными весами OSNet:

```sh
source_run=runs/product/20261107-073316-3bbd0f87
.venv/bin/python -m src.vision.appearance_experiment \
  --cameras "$source_run/cameras.json" \
  --observations "$source_run/vision/observations.jsonl" \
  --project "$source_run/project.json" --associate --color \
  --output runs/appearance/office-review-01
```

Выберите существующий завершённый прогон с первыми 180 секундами каждой камеры и доступными исходными файлами. Используйте его собственные пути, рамки, смещения и калибровку. Если калибровки нет, опустите `--project`, чтобы сравнить три режима без геометрии. Если готового прогона нет, сначала получите наблюдения через `src.vision run --max-duration-s 180 --local-buffer-s 5` с реальным конфигом камер и новым `--output`. Эксперимент сохраняет исходный интервал и исходный набор наблюдений с признаками, а не ищет новые кропы. В `--output` нужен новый каталог.

При отсутствии разметки `review_pairs.jsonl` содержит до 30 пар для ручного просмотра. Каждая строка содержит ссылки на кадры, время и оценки. Это подсказки. Для оценки сформируйте собственный JSONL, добавьте `--pairs` и выберите новый каталог. Пример формата с вымышленными ID:

```json
{"left":["cam01",125,"l2"],"right":["cam02",135,"l4"],"same_person":true,"same_episode":true,"split":"holdout"}
```

`same_person` используется для проверки внешности, `same_episode` — для проверки глобальных ID. Поле `same_episode` можно опустить для обычных пар. При возвращении того же человека в новом эпизоде укажите `same_episode: false`. Разделите `calibration` и `holdout` по людям или дублям. Подтвердите пары по видео. Добавьте сложные пары разных людей в похожей одежде, обычное освещение, перекрытия и тёмные участки. Пары используются только для оценки.

`experiment.json` содержит параметры модели, контрольные суммы конфигурации и наблюдений, время, число закодированных кропов и метрики размеченных пар. `--associate` строит глобальные ID для каждого режима с одинаковым профилем: 15 с, 0.72, 0.62, отрыв 0.03, бонус графа 0.04. Вывод показывает ложные склейки и разрывы на размеченных парах. Он не является IDF1/HOTA. `pair_scores.jsonl` содержит исходные оценки по каждой размеченной паре. Экспорт цвета и результаты не коммитятся. Глобальные пороги и способ добавления отдельного признака цвета согласует агент 1.

Режим для новых запусков vision:

```sh
.venv/bin/python -m src.vision run --cameras configs/cameras.local.json \
  --output runs/appearance/vision-gamma-01 --device cpu --max-duration-s 180 \
  --local-buffer-s 5 --appearance-preprocess gamma --appearance-gamma 0.8 \
  --appearance-dark-luma 80
```

## Проверка

```sh
.venv/bin/python -m pytest src/app/tests src/vision/tests src/association/tests -q
.venv/bin/python scripts/check_examples.py
```

Локально прошли 76 тестов. Отдельный технический прогон выполнен с проверенными весами OSNet, PyTorch 2.15.0 CPU и OpenCV 5.0.0.93. Два MJPG-ролика по четыре кадра при 5 FPS сделаны из [публичного bus.jpg](https://github.com/ultralytics/ultralytics/blob/main/ultralytics/assets/bus.jpg). Во втором яркость пикселей умножена на 0.35 до кодирования. Использованы две фиксированные рамки `[49,395,230,905]` и `[228,410,343,855]` при размере 810×1080. Это проверка пути обработки с настоящей моделью и искусственным затемнением одного ракурса.

| Режим | Среднее сходство 2 положительных пар | Среднее сходство 2 отрицательных пар | Разрывы / ложные склейки на этих парах |
|---|---:|---:|---:|
| raw | 0.945 | 0.386 | 0 / 0 |
| gamma | 0.941 | 0.343 | 0 / 0 |
| combined | 0.943 | 0.365 | 0 / 0 |

На этом коротком CPU-прогоне кодирование 16 кропов заняло около 0.20 с для каждого одиночного варианта и 0.40 с для обоих проходов вместе. Декодирование и загрузка модели в эти числа не входят. Цвет дал оценку лишь для одной из четырёх пар: тёмные области часто были недоступны. Исходные офисные видео и подтверждённый эталон на них в окружении проверки отсутствовали. Для выбора режима нужны независимые офисные эпизоды. Усиление теней может поднять шум, округление и преобразование цветовых пространств могут изменить цвет, а потерянные детали восстановить нельзя. До измерения пользы в продукте рекомендован `off`.
