# Прогноз Калмана и граф офиса

Включите режим, добавив в корень JSON проекта поле `"floor_prediction": "kalman"`.
Для контрольного прогона используйте `"floor_prediction": "heuristic"` или
прежний файл проекта без этого поля. База эксперимента — `7cece63`.

Фильтр оценивает координаты и скорость на плане по недавним проекциям нижнего
центра рамки. Для прогноза нужны хотя бы три наблюдения с разными временами
на интервале от 0.4 с. Окно истории ограничено 1.6 с. При разрыве в истории
больше 0.8 с ранние измерения отбрасываются. Если измерений мало, остаётся
слабая оценка близости к последней позиции.

Для пропусков до 4 с состояние переносится на время наблюдения кандидата.
Полуоси области соответствуют одному стандартному отклонению ошибки прогноза
с учётом шума измерения. Погрешность синхронизации дополнительно увеличивает
полуось вдоль оценённой скорости. Расстояние Махаланобиса преобразуется
в обычную мягкую геометрическую поправку проекта. Шум измерения задан как
`0.55 × радиус` (стандартное отклонение), интенсивность шума ускорения —
`(0.65 × масштаб плана)²`. Это стартовые значения для сравнения на записях.

Для направленного перехода с размеченными воротами используется существующий
маршрут по рёбрам `motion_model`. Уверенная скорость у выхода помогает оценить
время прохождения этого маршрута. Если скорость ненадёжна, точка у выхода
устарела или калибровка отсутствует, граф использует типовую скорость.
При условном масштабе граф переводит скорость в метры только по заданному
`meters_per_unit`. Для маршрута применяется одна пространственная оценка,
по времени прохода. При отсутствии пригодного маршрута короткий прогноз
пола доступен там, где есть проекции. Сравнение одновременных ракурсов
и восстановление по рамкам внутри одной камеры используют свои прежние
оценки. Итоговый ID по-прежнему зависит и от признаков внешности.

## Сравнение на сохранённых детекциях

Скопируйте проект с проверенной калибровкой и графом в два файла, например
`runs/project-heuristic.json` и `runs/project-kalman.json`. Укажите в них
соответствующие значения `floor_prediction`. Подставьте папку одного
завершённого прогона и используйте новые каталоги результатов.

```bash
source_run=runs/product/ИД_ГОТОВОГО_ПРОГОНА
for mode in heuristic kalman; do
  .venv/bin/python -m src.association \
    --cameras "$source_run/cameras.json" \
    --observations "$source_run/vision/observations.jsonl" \
    --project "runs/project-$mode.json" \
    --output-dir "runs/floor-$mode" \
    --decision-mode balanced --fragment-mode boundary \
    --timeout-s 60 --similarity-threshold 0.72 --tracklet-threshold 0.62 \
    --ambiguity-margin 0.03
done
```

В приложении для такого сравнения можно выбрать один готовый прогон
и использовать «Тест балансировки ID» или один и тот же профиль кнопки
«Проверить фрагменты» с каждым из двух проектов. В `reconciliation.json`
видны выбранный прогноз, покрытие проекций и свидетельства при склейке.
Сравнивайте ложные склейки, разрывы ID и правильные переходы на одних
и тех же временных отрезках. Для ручной проверки особенно важны проходы
через поворот, остановки у двери и люди, выходящие друг за другом.

В синтетическом тесте на маршруте длиной 10 м с поворотом контрольный режим
оставил два ID, а Калман с оценкой скорости у выхода связал фрагменты одного
человека. Проверены отказ обратному переходу, переход на типовую скорость
при остановке и расширение области при росте пропуска. Офисные видео и
размеченные эпизоды в рабочей копии отсутствовали. Выигрыш на реальных
записях ещё предстоит измерить.
