# Ручной тест полного базового продукта

## Перед съёмкой
- Неподвижные камеры/телефоны, неизменный зум. В кадре виден пол и по возможности ноги людей.
- Для проверки реального совместного обзора нужны минимум два устройства, снимающие одновременно. Один телефон в разных ракурсах проверяет переходы, но не одновременное усреднение.
- Подготовить простую схему с измеренными размерами и четыре заметных ориентира пола на каждый ракурс. Нужны разнесённые точки, не лежащие на одной прямой.
- Для одновременных роликов обеспечить общее начало или записать известные смещения. Приложение не синхронизирует их автоматически по звуку.

## Настройка
1. Открыть office_editor.command в корне проекта.
2. Нарисовать схему, добавить камеры и выбрать новые видео. Старые запуски сохраняются отдельно.
3. Задать начало записи каждой камеры и связи: общие зоны отдельно от направленных переходов.
4. Выполнить привязку 4+4 точек и проверить ещё 2-3 точки пола, которые не участвовали в вычислении.
5. Открыть «Просмотр и запуск», оставить CPU и N=1 для первого контрольного прогона. Записать использованные пороги.

## Сценарии
- [ ] Один человек переходит между камерами: ID сохраняется.
- [ ] Один человек виден одновременно в общей зоне: один глобальный ID, счётчик не удваивается.
- [ ] Два человека одновременно в одной камере: разные ID.
- [ ] Два человека в похожей одежде: ID не смешиваются при пересечении и переходе.
- [ ] Краткое перекрытие: наблюдения могут пропасть, но подтверждённый трек восстанавливается.
- [ ] Человек отсутствует на всех камерах больше 10 с: после возвращения новый ID.
- [ ] Одновременные проекции на полу близки: показывается общая позиция.
- [ ] Искусственно неправильная привязка одной камеры: конфликт виден, ложного среднего нет. Для этого лучше использовать копию проекта.
- [ ] Выбор рамки/строки меняет выбранный трек и отдельную траекторию.
- [ ] Пауза, перемотка и вкладка «Камеры» соответствуют времени роликов.
- [ ] Счётчик совпадает с числом строк итогового CSV, сквозной ID через 2+ камеры считается один раз.
- [ ] Повтор CPU-запуска того же проекта и настроек даёт одинаковые ID и число треков.

## Что прислать после теста
- Примерное ожидаемое число эпизодов/людей и кто когда переходит.
- ID, камера и время каждого заметного разрыва или склейки.
- ID запуска (виден в адресной строке просмотра), выгруженная настройка запуска и tracks.csv.
- Отдельно: ошибка ID или ошибка проекции пола. Если точка уехала на плане, но ID правильный, это другой класс проблемы.

До истечения 10 с после выхода трек может сохраняться: это известное упрощение. Дополнительные короткие ложные треки не удаляются вручную из результата. Порог 0.65 не гарантирует разделение новых людей — проверка нужна именно на новом материале.
