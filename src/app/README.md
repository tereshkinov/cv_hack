# Агент 3 / Локальный редактор офиса

Первая стадия интерфейса: прямая разметка стен, установка камер, настройка схематических секторов и привязка неподвижных камер к плоскости пола по четырём парам точек. Это редактор настройки; воспроизведение глобальных треков на плане и слияние позиций нескольких камер ещё не подключены.

## Запуск на MacBook

В корне проекта дважды открыть `office_editor.command`. Он запускает локальный сервер и открывает браузер. Уже созданное `.venv` с зависимостями vision подходит; дополнительных веб-библиотек не требуется. Окно терминала оставить открытым. Остановить сервер: Ctrl+C в этом окне.

Из корня проекта вручную:

```sh
.venv/bin/python -m src.app --open
```

Адрес: http://127.0.0.1:8765 . Если порт занят, выбрать другой: `--port 8766`. Привязка только к loopback; приложение не публикуется в интернете. Данные и видео обрабатываются локально.

## Настройка

1. Задать ширину и глубину схемы в метрах. Начальные 20x14 м условные, а не измерения офиса. Изменение размера не растягивает уже нарисованную геометрию. Существующие элементы должны помещаться в новый размер.
2. Выбрать «Прямая стена». Два клика задают сегмент; следующие два — следующий сегмент. Esc отменяет незавершённую стену. Есть отмена последней стены и удаление выбранной стены. Сетка 0.25 м опциональна.
3. Выбрать «Добавить камеру» и щёлкнуть по схеме. В режиме выбора камеру можно перетаскивать. Название, высота, направление, угол и дальность схематического сектора задаются полями.
4. Выбрать видео из `data/raw/` или загрузить файл с компьютера. Через ползунок выбрать удобный кадр с видимым полом. MOV декодируется сервером в JPEG, поэтому поддержка MOV браузером не требуется.
5. В кадре последовательно отметить четыре заметные точки **плоского пола**. На плане выбрать «Точки на плане» и отметить те же четыре точки в том же порядке. Рядом показаны пары с номерами 1-4 и числовыми координатами.
6. Нажать «Рассчитать привязку». Затем «Проверить кликом»: клик по другой точке пола в кадре показывает её x,y и зелёную отметку на схеме. Для точки за пределами схемы отображается предупреждение.
7. Проект сохраняется автоматически. Можно скачать JSON и открыть его позднее. Стены и камеры сохраняются вместе с исходными точками и вычисленной матрицей. Привязка при импорте пересчитывается из исходных точек.

Начало координат слева сверху; x вправо, y вниз. Схема — метры, кадр — исходные пиксели. Номера опорных точек не переставляются автоматически: пользователь подтверждает соответствие кликами. Можно удалить последнюю точку каждой стороны или сбросить всю разметку.

## Геометрия и ограничения

`geometry.calibrate()` вычисляет гомографию pixel -> floor, `geometry.project()` переносит точки. Проверяются четыре пары конечных координат, совпадающие/коллинеарные точки, пересечение горизонта внутри опорного четырёхугольника и остаток на опорных точках. Четыре точки дают точное соответствие этих опорных точек в пределах численной погрешности, но не доказывают точность между ними или вне них. Рекомендуется проверить дополнительные ориентиры пола. Исправление дисторсии объектива пока не реализовано.

Фиксированные камера, фокусное расстояние/зум и плоский пол — предположения. Изменение положения телефона/зум во время записи нарушает фиксированную привязку. В трекинге нужно будет проецировать точку у ног, а не центр рамки и не произвольную точку тела.

Высота камеры, направление и угол пока используются только для отображения **условного** сектора. Они не выдают точную физическую границу обзора, не учитывают перекрытие стенами и не определяют матрицу привязки. Реальных intrinsics/наклона для такого расчёта пока нет. Пересечение секторов не записывается автоматически как подтверждённая топология.

## Хранение

- `configs/office.local.json`: текущий пользовательский проект, исключён из Git.
- `runs/app/uploads/`: локальные копии загруженных видео, исключены из Git.
- JSON содержит локальные идентификаторы видео; при переносе проекта нужно перенести видео с сохранением относительных путей или выбрать источники заново.
- Редактор использует отдельный формат настройки. Конфигурацию vision/association автоматически не перезаписывает, общий контракт v1 не меняет.
- Проверка интерфейса выполнялась на `runs/app-qa/project.json`; произвольные тестовые размеры и точки оттуда не являются разметкой офиса пользователя и не копируются в основной проект.

## Проверки

```sh
.venv/bin/python -m pytest src/app/tests src/vision/tests src/association/tests -q
```

Проверяются известное перспективное преобразование и независимые точки, вырожденные/неконечные опоры, горизонт, импорт с пересчётом матрицы, сохранение/повторное чтение JSON, HTTP-ошибки некорректной привязки. В браузере проверены стены, камера, чтение пользовательского MOV, ввод 4+4 точек, вычисление и проверочный клик. Следующий этап: подключение реальных глобальных треков, отображение пути и объединение одновременных координат.
