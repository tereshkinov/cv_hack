# Агент 2: межкамерное сопоставление и глобальные ID

Модуль реализует собственную детерминированную логику association поверх контракта
`schema_version = 1` из `docs/contracts.md`. Общий контракт не изменён.

## Что реализовано

- фильтрация кандидатов по времени и топологии камер;
- разные правила для `overlap_with` и направленного `transition_to`;
- cosine-сопоставление только признаков одной модели и одной размерности;
- галерея до пяти наиболее качественных embedding вместо безусловного усреднения кадров;
- консервативный отказ от неоднозначного совпадения;
- единый ID при одновременном наблюдении в перекрывающихся камерах;
- запрет appearance-склейки разных локальных треков одной камеры;
- состояния `active`, `pending`, `closed`, настраиваемый timeout (по умолчанию 60 с);
- восстановление на границе timeout включительно и новый ID после границы;
- окончание трека по времени последнего наблюдения;
- `end_of_video`, `timeout` и опциональный `explicit_exit` как причины закрытия;
- атомарный и воспроизводимый экспорт `assignments.jsonl` и `tracks.json`.

## Входы и выходы

Входы:

- JSON конфигурации камер: `Camera` из общего контракта;
- JSONL наблюдений: `Observation` из общего контракта;
- опциональный JSONL подтверждённых событий выхода (расширение модуля, см. ниже).

Выходы:

- `assignments.jsonl`: ссылка на наблюдение, `global_track_id`, `match_score`, `reason`;
- `tracks.json`: итоговый список `GlobalTrack`.

Embedding должен сопровождаться `embedding_model_id`. Признаки разных моделей или размерностей
не сравниваются. `timestamp_s` уже должен быть временем от общего начала видео; модуль не применяет
`time_offset_s` второй раз.

## Быстрый запуск

Из корня репозитория:

```bash
source .venv/bin/activate
python -m src.association \
  --cameras examples/cameras.json \
  --observations examples/observations.jsonl \
  --output-dir runs/association-baseline \
  --allow-topology-only-baseline
```

В примерах репозитория embedding отсутствуют, поэтому команда выше явно включает baseline.
Для реального экспорта с embedding флаг `--allow-topology-only-baseline` не нужен:

```bash
python -m src.association \
  --cameras path/to/cameras.json \
  --observations path/to/observations.jsonl \
  --output-dir runs/association
```

Параметры:

- `--timeout-s 60.0` - ожидание по `last_seen` всего глобального трека;
- `--similarity-threshold 0.75` - стартовый технический порог, не требование организаторов;
- `--ambiguity-margin 0.05` - минимальный отрыв лучшего кандидата от второго;
- `--min-embedding-confidence 0.50` - минимальная confidence наблюдения для галереи;
- `--gallery-size 5` - число лучших embedding глобального трека.

Порог 0.75 требует настройки на реальном эталоне и проверочном дубле. Его нельзя считать
проходным баллом хакатона.

## Явный выход

Источник события выхода командой пока не согласован, поэтому этот вход выключен по умолчанию.
После согласования можно передать `--exits file.jsonl`. Строка имеет вид:

```json
{"schema_version":1,"camera_id":"cam01","local_track_id":"l1","timestamp_s":7.2}
```

Событие означает подтверждённый выход **глобального** трека из всех ракурсов, а не простой выход
из одной камеры. Оно закрывает трек с `end_s = last_seen_s`. Неизвестная локальная ссылка считается
ошибкой входа.

## Baseline без embedding

Без признаков новый локальный трек по умолчанию всегда получает новый global ID. Явный флаг
baseline разрешает склейку только когда после временной и топологической фильтрации остаётся ровно
один кандидат. При неоднозначности создаётся новый ID. Поле `reason` получает значение
`overlap_topology_baseline` или `transition_topology_baseline`, чтобы результат нельзя было принять
за ReID.

## Известные ограничения

- Связка с реальным экспортом vision проверена на первых трёх роликах команды; для оценки точности нужны новые независимые записи.
- `overlap_with` трактуется симметрично, `transition_to` - направленно.
- Appearance не склеивает разные локальные ID одной камеры. Это консервативно защищает от ложной
  склейки, но не чинит фрагментацию локального трекера внутри одной камеры.
- При отсутствии согласованного события выхода timeout может сохранить ID человеку, который вышел
  и вернулся менее чем через 60 секунд. Это известное отклонение от строгого правила ТЗ.
- Галерея использует `detection_confidence` как доступный показатель качества. После расширения
  контракта агентом 1 можно подключить отдельную оценку качества/окклюзии.

## Исправление: повторная офлайн-проверка по нескольким кадрам

После первичного прохода по умолчанию выполняется пересмотр **неподтверждённых межкамерных связей**. Если первый кадр плохой или без embedding, его предварительный ID больше не остаётся окончательным автоматически: второй проход сравнивает накопленные описания треков и при подтверждении переписывает ID всех наблюдений объединяемого трека, включая первые кадры.

Для каждой стороны нужно минимум три качественных embedding с разных моментов времени (интервал не менее 0.2 с). До 32 образцов выбираются равномерно по времени. Оценка пары - среднее двух медиан ближайших cosine-совпадений в обоих направлениях. Один удачный кадр не заменяет согласованность нескольких наблюдений. Кандидаты должны быть взаимно лучшими с отрывом `ambiguity_margin`, в том числе от конкурентов ниже порога. При равных/близких кандидатах склейки нет.

Сохраняются направленность переходов, timeout, разделение пространств признаков. Второй проход не склеивает группы, содержащие одну и ту же камеру, и не восстанавливает связи через подтверждённый явный выход. Для перехода без общей зоны интервалы наблюдения должны быть последовательными. Совпадающий локальный ID, повторно появившийся после timeout, не становится основанием для объединения. После объединения список итоговых треков и ID в assignments согласованы. Причина исправления: `offline_multiframe_reid`, подробности: `reconciliation.json`.

Это офлайн-уточнение: используются будущие кадры записи. Оно умеет исправлять пропущенные связи, но не разделяет уже ошибочно склеенные первым проходом треки. Длинные записи требуют дополнительной оптимизации: число пар предварительных треков может расти квадратично, хотя галереи ограничены.

Параметры:
- `--no-offline-reconcile`: воспроизвести прежний режим первого кадра.
- `--tracklet-min-samples 3`: минимум временно разнесённых embedding с каждой стороны.
- `--tracklet-threshold`: отдельный порог второго прохода; по умолчанию равен `--similarity-threshold` (0.75). Порог первого прохода при этом не меняется.

### Проверка на трёх пользовательских роликах

Ролики сняты последовательно одним телефоном, паузы 2 с. `cam01`/`cam02` имеют общую зону; `cam02 -> cam03` - подтверждённый переход без общей зоны. Это проверка смены ракурса, а не одновременного обзора.

При стандартном пороге 0.75 два первых основных локальных трека теперь объединяются (score 0.7563). Для связи с третьим ракурсом требуется более низкий порог: score 0.6788. Для разработки выбран **0.65**, настроенный на этих же роликах; обобщение на других людей и новые записи не проверено. Это не значение, установленное организаторами, и не новое универсальное значение по умолчанию.

```sh
.venv/bin/python -m src.association \
  --cameras configs/cameras.local.json \
  --observations runs/three-cameras-01/vision/observations.jsonl \
  --output-dir runs/three-cameras-02/association \
  --tracklet-threshold 0.65
```

Результат разработки: 453 назначения, основной локальный `l1` всех трёх камер относится к `g1`, общее число итоговых треков 5 вместо 7. Четыре дополнительных коротких локальных трека не удалялись для получения красивого счётчика; нужно отдельно проверить их происхождение. Повторный экспорт совпал побайтово. Нужны новые записи с несколькими людьми и похожей одеждой, чтобы оценить ложные склейки при пороге 0.65.
