# Агент 1: видео -> локальные треки и признаки

Реализован офлайн-модуль. Глобальные ID, межкамерные решения и закрытие сквозного трека здесь **не выполняются**.

## Быстрый старт

Из корня проекта; проверено на macOS arm64, Python 3.13, CPU. Linux/CUDA и MPS пока не проверены; `resource` требует Unix.

```sh
python3.13 -m venv .venv
.venv/bin/python -m pip install -r src/vision/requirements-lock.txt
.venv/bin/python -m src.vision prepare
mkdir -p data/raw/cam01 data/raw/cam02
cp configs/cameras.local.example.json configs/cameras.local.json
```

Положить ролики в `data/raw/cam01/video.mp4` и `data/raw/cam02/video.mp4`. Другие имена/форматы можно указать в локальной конфигурации. `data/`, веса, результаты и локальный конфиг игнорируются Git. Все пути в camera.video_path считаются от корня проекта, не от файла конфигурации.

```sh
.venv/bin/python -m src.vision inspect data/raw/cam01/video.mp4 data/raw/cam02/video.mp4
.venv/bin/python -m src.vision run --cameras configs/cameras.local.json --output runs/vision-001 --device cpu --preview
```

Каталог результата должен быть новым; перезапись запрещена. `prepare` скачивает около 15 MB весов, установленные зависимости занимают существенно больше места. В `models/provenance.json` сохраняются источники и SHA256. Загрузка OSNet проверяет SHA256 и полноту всех слоёв, кроме ненужного классификатора.

`overlap_with` и `transition_to` в примере пусты: реальные отношения ещё не известны, их заполняет команда. Модуль vision их не интерпретирует. Ширина, высота и FPS берутся из видео и записываются в отчёт; выдуманные размеры камер не требуются.

## Выходы для агентов 2 и 3

- `observations.jsonl`: контракт Observation v1, отсортирован по `(timestamp_s, camera_id, local_track_id)`. Координаты float, исходные пиксели; frame_index с нуля. `local_track_id` - строка `l1`, `l2`, ...; ключ трека - **пара camera_id + local_track_id**. Одинаковый номер разных камер не означает одного человека.
- `observations-camera-N.jsonl`: тот же формат до общего слияния; N соответствует порядку камер в конфиге.
- `tracklets.json`: дополнительный производный файл, не изменение общего контракта. Для каждого локального трека - начало, последнее наблюдение, число наблюдений, индексы выбранных кадров и L2-нормализованное среднее до пяти качественных дескрипторов. Это описания внешности для агента 2, а не глобальные личности.
- `run.json`: фактические параметры видео, версии, модель признаков, число наблюдений, время, FPS обработки, память и соответствие камеры файлу предпросмотра.
- `preview-N.mp4`: диагностические рамки с **локальными** ID. Не заменяет обязательное демо с глобальными ID.
- `FAILED.json`: запуск не завершён; частичные файлы не использовать как полный результат.

Embedding в Observation **разреженный**: только при получении нового качественного кропа, не чаще `--embedding-interval-s` (по умолчанию 0.5 с) на локальный трек. Остальные наблюдения остаются без embedding, как разрешено контрактом. Потребитель объединяет наблюдения по составному ключу; не удаляет наблюдения без embedding. Для офлайн-сопоставления можно использовать tracklets.json, но его среднее использует весь локальный трек и недоступно заранее в онлайн-режиме.

OSNet: 512 float, RGB 256x128, ImageNet mean/std, L2. `embedding_model_id` содержит архитектуру, датасет и SHA256. Сравнивать только одинаковые model_id. `--embedding color` даёт явно маркированный HSV-baseline из 384 признаков, который легко путает похожую одежду. `--embedding none` отключает признаки и не обеспечивает межкамерное различение внешности.

## Настройки и ограничения

- По умолчанию YOLO11n, person-only, ByteTrack, 640, CPU, детекция каждого кадра. `--device mps` / `--device 0` возможны, но требуют проверки на целевом устройстве.
- ByteTrack хранится отдельно для каждой камеры. Локальный буфер `--local-buffer-s 1` не заменяет глобальный timeout 10 с. Локальный ID может разорваться при перекрытии: восстановление глобального ID остаётся агенту 2. Порог локального буфера требует настройки на живом видео.
- `--frame-stride 2` уменьшает частоту обработки; timestamp и frame_index остаются исходными. Пропущенные кадры не экспортируются, интерполяции нет. Предпросмотр имеет FPS исходного видео / stride.
- Слабые кропы отбрасываются по высоте, резкости и перекрытию рамок. Значения по умолчанию - стартовые параметры, не требования. Перекрытие рамок не является точной оценкой окклюзии. Маленький или размытый человек может иметь трек без признаков.
- Время: `timestamp_s = frame_index / fps + time_offset_s`. Положительный offset означает более позднее начало камеры относительно общего нуля. Отрицательные времена не экспортируются. Самостоятельной синхронизации по звуку/содержимому нет. Предполагается постоянная частота кадров; VFR сначала привести к CFR с проверкой синхронности.
- Повреждённый хвост файла может выглядеть как конец чтения OpenCV; проверяйте длительность/число кадров в run.json. `--max-frames` - диагностическое ограничение по исходным кадрам каждой камеры.
- Память не растёт с числом наблюдений: они пишутся на диск и сливаются потоком. До top_k векторов сохраняется на каждый локальный трек; число локальных треков всё же влияет на память. Дополнительно хранятся per-camera JSONL, поэтому есть дублирование на диске.
- Воспроизводимость CPU проверена побайтово на техническом прогоне. На других устройствах/версиях это нужно проверить отдельно.

## Проверки

```sh
.venv/bin/python -m pytest src/vision/tests -q
```

Тесты используют синтетические видео и подменённый детектор, чтобы проверить контракты, временные пропуски, изоляцию камер, координаты и признаки; они не измеряют точность YOLO/ReID.

Фактический технический прогон с загруженными YOLO11n и OSNet: два ролика по 15 кадров, 5 FPS, 640x640, повтор публичного bus.jpg с двумя чёрными кадрами. Получены 104 наблюдения, 8 локальных треков (по 4 на источник), 40 embedding по 512 признаков. На чёрных кадрах наблюдений нет; после пропуска локальные ID восстановились. Это **не реальные две камеры и не оценка MTMC**. Источник картинки: https://github.com/ultralytics/ultralytics/blob/main/ultralytics/assets/bus.jpg . Видео и веса в Git не добавлены.

На этой машине первый технический прогон занял около 7.0 с, 4.29 обработанных кадра/с, пик RSS около 501 MB. Время включает инициализацию моделей внутри run, но не установку зависимостей, загрузку весов и начальный импорт CLI. Это короткий технический замер, не прогноз для офисной записи.

Источники компонентов и лицензии: THIRD_PARTY.md. Качество на видео команды ещё не измерено. Общий контракт в docs/contracts.md не изменён. Разреженные embedding подключены к association; офлайн-уточнение использует несколько кадров. Единый запуск и просмотр доступны через office_editor.command.

Повторный технический запуск: около 3.0 с / 9.93 кадра/с после прогрева системных кэшей; observations.jsonl и tracklets.json совпали побайтово. Машинный отчёт: validation.json. Минимальный пример фактического вывода моделей: fixtures/technical_observations.jsonl; происхождение синтетического входа указано рядом.

## Посмотреть трекинг одного видео

На macOS открой в Finder файл `debug_video.command` в корне проекта двойным щелчком. Выбери видео в диалоге. После обработки откроется видеоплеер. Пауза, перемотка и скорость доступны средствами плеера. Окружение `.venv` и веса должны быть установлены по инструкции выше; в текущей рабочей папке они уже установлены.

Без диалога, из корня проекта:

```sh
.venv/bin/python -m src.vision debug "/полный/путь/к/видео.mp4" --open
```

Результат автоматически помещается в новый `runs/debug/<дата-время>/`:
- `tracked.mp4`: цветные рамки, локальный ID и confidence, следы последних наблюдений, время/номер кадра, число видимых и всего встреченных локальных ID.
- `tracks.csv`: ID, первое/последнее наблюдение, число наблюдений; удобно замечать короткие обрывы.
- `observations.jsonl`, `tracklets.json`, `run.json`, `README.txt`: данные и параметры отладки.

След показывает нижний центр рамки в координатах изображения, а не точное положение на плане. Следы не соединяются через длинные пропуски и не рисуются для невидимых людей. Цвета могут повторяться при большом числе треков; идентификатор указан текстом. Это проверка локального трекера одной камеры, без глобальных ID. По умолчанию OSNet выключена для скорости; добавить `--embedding osnet`, если нужен экспорт признаков внешности.

Для короткой проверки начала длинного ролика:

```sh
.venv/bin/python -m src.vision debug "data/raw/cam01/video.mp4" --max-frames 300 --open
```

Обработка выполняется до просмотра, без прямого показа в реальном времени. Прогресс печатается каждые 100 кадров. Исходный файл не меняется.
